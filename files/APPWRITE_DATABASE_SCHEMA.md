# Appwrite Database Schema for HICv

## 📊 Database Structure

Create a new database in Appwrite Console and add the following collections:

---

## 🗄️ **Collections to Create:**

### **1. Collection: `users`**

**Collection ID:** `users`
**Permissions:**

- Read: Users (own documents only)
- Create: Users
- Update: Users (own documents only)
- Delete: Admins only

**Attributes:**

| Attribute            | Type     | Size | Required | Default | Array | Description                                          |
| -------------------- | -------- | ---- | -------- | ------- | ----- | ---------------------------------------------------- |
| `email`              | Email    | 320  | Yes      | -       | No    | User's email address                                 |
| `name`               | String   | 255  | No       | -       | No    | User's full name (auto-filled from CV)               |
| `phone`              | String   | 50   | No       | -       | No    | User's phone number (auto-filled from CV)            |
| `summary`            | String   | 1000 | No       | -       | No    | Professional summary (auto-filled from CV)           |
| `experience`         | String   | 1000 | No       | -       | No    | Work experience (auto-filled from CV)                |
| `education`          | String   | 1000 | No       | -       | No    | Education details (auto-filled from CV)              |
| `skills`             | String   | 2000 | No       | -       | No    | Skills list (auto-filled from CV) - INCREASED SIZE   |
| `isAdmin`            | Boolean  | -    | No       | false   | No    | Admin user flag                                      |
| `isLicensed`         | Boolean  | -    | No       | false   | No    | License status for API access                        |
| `licenseKey`         | String   | 50   | No       | -       | No    | License key for activation                           |
| `licenseActivatedAt` | DateTime | -    | No       | -       | No    | License activation timestamp                         |
| `apiKeyHash`         | String   | 255  | No       | -       | No    | Hashed API key for authentication                    |
| `apiUsageMonth`      | String   | 10   | No       | -       | No    | Current month for API usage (YYYY-MM)                |
| `apiUsageCount`      | Integer  | -    | No       | 0       | No    | API calls count for current month                    |
| `apiRateLimit`       | Integer  | -    | No       | 500     | No    | API calls limit per month                            |
| `cvCount`            | Integer  | -    | No       | 0       | No    | Legacy CV count (deprecated)                         |
| `cvLimit`            | Integer  | -    | No       | 3       | No    | Legacy CV limit (deprecated)                         |
| `uiCvCount`          | Integer  | -    | No       | 0       | No    | UI CV generation count for current month             |
| `uiCvLimit`          | Integer  | -    | No       | 5       | No    | UI CV generation limit per month                     |
| `uiCvMonth`          | String   | 10   | No       | -       | No    | Current month for UI CV tracking (YYYY-MM)           |
| `plan`               | String   | 50   | No       | free    | No    | Subscription plan (free/premium/enterprise/lifetime) |

**Note:**

- Document ID (`$id`) is the Firebase User ID (UID) - NOT a separate field
- `$createdAt` and `$updatedAt` are auto-generated by Appwrite - do NOT create these fields manually

**Indexes:**

- `email` (unique, key)
- `isAdmin` (key)
- `isLicensed` (key)

---

### **2. Collection: `cvs`**

**Collection ID:** `cvs`
**Permissions:**

- Read: Users (own documents only)
- Create: Users
- Update: Users (own documents only)
- Delete: Users (own documents only)

**Attributes:**

| Attribute        | Type                       | Size  | Required | Default | Array |
| ---------------- | -------------------------- | ----- | -------- | ------- | ----- |
| `users`          | Relationship (many-to-one) | -     | Yes      | -       | No    |
| `fileName`       | String                     | 255   | Yes      | -       | No    |
| `fileId`         | String (bucket storage ID) | 255   | Yes      | -       | No    |
| `rawText`        | String                     | 50000 | No       | -       | No    |
| `structuredData` | String (JSON)              | 50000 | No       | -       | No    |
| `profileData`    | String (JSON)              | 50000 | No       | -       | No    |

**Note:**

- Document ID (`$id`) is auto-generated by Appwrite
- `users` field is a **Relationship** to the `users` collection (many-to-one)
- `$createdAt` and `$updatedAt` are auto-generated by Appwrite - do NOT create these fields manually

**Indexes:**

- `users` (key) - for querying CVs by user
- `fileId` (key)

---

### **3. Collection: `licenses`**

**Collection ID:** `licenses`
**Permissions:**

- Read: Any authenticated user
- Create: Admins only
- Update: Admins only
- Delete: Admins only

**Attributes:**

| Attribute     | Type     | Size | Required | Default | Array |
| ------------- | -------- | ---- | -------- | ------- | ----- |
| `key`         | String   | 50   | Yes      | -       | No    |
| `createdAt`   | DateTime | -    | Yes      | -       | No    |
| `createdBy`   | String   | 255  | Yes      | -       | No    |
| `activatedBy` | String   | 255  | No       | -       | No    |
| `activatedAt` | DateTime | -    | No       | -       | No    |
| `isActive`    | Boolean  | -    | Yes      | true    | No    |
| `notes`       | String   | 1000 | No       | -       | No    |

**Note:**

- Document ID (`$id`) is auto-generated by Appwrite
- `createdAt` is a **MANUAL DateTime field** that you must create in Appwrite Console
  - This is NOT auto-generated - you must add it as a regular DateTime attribute
  - Used to track when admin created the license
  - Code will set this value when creating licenses
- `activatedAt` is set when a user redeems the license
- Appwrite also auto-generates `$createdAt` and `$updatedAt` (not shown in table)

**Indexes:**

- `key` (unique, key)
- `isActive` (key)
- `createdAt` (key) - for sorting licenses by creation date

---

### **4. Collection: `api_keys`**

**Collection ID:** `api_keys`
**Permissions:**

- Read: Users (own documents only)
- Create: Users
- Update: Users (own documents only)
- Delete: Users (own documents only)

**Attributes:**

| Attribute    | Type                       | Size | Required | Default | Array |
| ------------ | -------------------------- | ---- | -------- | ------- | ----- |
| `users`      | Relationship (many-to-one) | -    | Yes      | -       | No    |
| `keyHash`    | String                     | 255  | Yes      | -       | No    |
| `keyPreview` | String                     | 50   | Yes      | -       | No    |
| `lastUsedAt` | DateTime                   | -    | No       | -       | No    |
| `isActive`   | Boolean                    | -    | Yes      | true    | No    |

**Note:**

- Document ID (`$id`) is auto-generated by Appwrite
- `users` field is a **Relationship** to the `users` collection (many-to-one)
- `$createdAt` is auto-generated by Appwrite (used instead of manual `createdAt`)

**Indexes:**

- `users` (key) - for querying API keys by user
- `keyHash` (key)
- `isActive` (key)

---

### **6. Collection: `job_applications`** (Optional)

**Collection ID:** `job_applications`
**Permissions:**

- Read: Users (own documents only)
- Create: Users
- Update: Users (own documents only)
- Delete: Users (own documents only)

**Attributes:**

| Attribute           | Type                       | Size | Required | Default | Array |
| ------------------- | -------------------------- | ---- | -------- | ------- | ----- |
| `users`             | Relationship (many-to-one) | -    | Yes      | -       | No    |
| `cvId`              | String                     | 255  | Yes      | -       | No    |
| `jobTitle`          | String                     | 255  | Yes      | -       | No    |
| `company`           | String                     | 255  | Yes      | -       | No    |
| `jobDescription`    | String                     | 5000 | No       | -       | No    |
| `coverLetter`       | String                     | 5000 | No       | -       | No    |
| `applicationStatus` | String                     | 50   | Yes      | pending | No    |

**Note:**

- Document ID (`$id`) is auto-generated by Appwrite
- `users` field is a **Relationship** to the `users` collection (many-to-one)
- `cvId` is a String field (not a relationship) - stores the CV document ID
- `$createdAt` and `$updatedAt` are auto-generated by Appwrite - do NOT create these fields manually

**Indexes:**

- `users` (key) - for querying applications by user
- `applicationStatus` (key)

## 🔐 **Permissions Setup:**

### **For Regular Users:**

```
Read: document.userId == $userId
Create: true
Update: document.userId == $userId
Delete: document.userId == $userId
```

### **For Admins:**

```
Read: true
Create: true
Update: true
Delete: true
```

### **For Licenses Collection:**

```
Read: true (any authenticated user)
Create: users.isAdmin == true
Update: users.isAdmin == true
Delete: users.isAdmin == true
```

## 📝 **Environment Variables Needed:**

Add these to your `.env.local`:

```env

# Appwrite Collections
NEXT_PUBLIC_APPWRITE_USERS_COLLECTION_ID=users
NEXT_PUBLIC_APPWRITE_CVS_COLLECTION_ID=cvs
NEXT_PUBLIC_APPWRITE_LICENSES_COLLECTION_ID=licenses
NEXT_PUBLIC_APPWRITE_API_KEYS_COLLECTION_ID=api_keys
NEXT_PUBLIC_APPWRITE_API_USAGE_LOGS_COLLECTION_ID=api_usage_logs
NEXT_PUBLIC_APPWRITE_JOB_APPLICATIONS_COLLECTION_ID=job_applications
```

## 🚀 **Setup Steps:**

1. **Create Database:**

   - Go to Appwrite Console
   - Click "Databases"
   - Click "Create Database"
   - Name: `hicv_database`
   - Copy the Database ID

2. **Create Collections:**

   - For each collection above, click "Create Collection"
   - Set Collection ID as specified
   - Add all attributes as listed
   - Create indexes as specified

3. **Set Permissions:**

   - For each collection, go to Settings → Permissions
   - Add permissions as specified above

4. **Update Environment Variables:**
   - Add all collection IDs to `.env.local`
   - Restart dev server

## ✅ **Benefits of This Structure:**

1. **Proper Admin Access:** Admins can access all data without permission issues
2. **Custom CV Limits:** Each user can have a custom `cvLimit` (default 3)
3. **Better Performance:** Indexed queries for fast data retrieval
4. **Scalability:** Can handle millions of records
5. **Security:** Proper RBAC with Appwrite permissions
6. **Flexibility:** Easy to add new fields or collections
